# Bundle Notebook Content

Use this skill when adding or updating a notebook page in `posts/` or
`courses/`. It prepares source notebooks for the zip bundles generated by the
site build. The bundle itself is produced by `just build` or `just
build-bundles`, then copied to friendly public routes by `just publish-routes`.

## Inputs

- Blog notebook: `posts/<slug>/index.ipynb`
- Learning notebook: `courses/<slug>/index.ipynb`

Skip markdown-only and QMD pages.

## Procedure

1. Check data and image references in code and markdown cells.
   Look for `read_csv`, `loadtxt`, `genfromtxt`, `open`, `np.load`,
   `pickle.load`, and markdown image links. Confirm referenced files exist
   relative to the notebook folder, usually under `assets/` or `data/`.

2. Inject or refresh PEP 723 dependency metadata.

   ```bash
   python3 _scripts/inject_juv_metadata.py --posts-dir posts
   python3 _scripts/inject_juv_metadata.py --posts-dir courses
   ```

   The option name remains `--posts-dir` for now, but it accepts either content
   root. The script is idempotent and removes old `ipynb: default` frontmatter.

3. Verify the metadata cell.
   Cell index 1 should be a hidden code cell containing `# /// script`.
   Dependencies should match imports in the notebook. Pyodide-incompatible
   packages such as `torch`, `pymc3`, `theano-pymc`, `theano`, `pymc`, and
   `lxml` should make the page download-only.

4. Build and inspect bundles.

   ```bash
   just build
   python3 _scripts/test_bundles.py --site-dir _site --report _site/test-report.json --timeout 600 --slug <slug>
   ```

5. Check public route behavior.
   Blog notebooks should work at `/posts/<slug>/` and `/blog/<slug>/`.
   Learning notebooks should work at `/learning/<slug>/` after route publishing.

## Notes

- Zip bundles replace Quarto `ipynb: default` downloads.
- Do not hand-write bundle zips. They are generated artifacts.
- If a notebook references files that cannot be found, stop and record the
  blocker before claiming the bundle is ready.
